# Scoped Stores

Scoped stores are child stores that inherit all state from their parent but can
override values independently. Think of them as a "fork" of state — reads fall
through to the parent, but writes stay local.

This is useful for modals, multi-step forms, drag previews, multi-tenant UIs, or
any scenario where you need isolated copies of shared state.

## How it works

```ts
import { atom, store } from "valdres"

const nameAtom = atom("Alice")
const rootStore = store()

// Create a scoped child store
const childStore = rootStore.scope("child-1")
```

### Reading: inherits from parent

```ts
rootStore.set(nameAtom, "Alice")
childStore.get(nameAtom) // "Alice" — falls through to parent
```

### Writing: stays local

```ts
childStore.set(nameAtom, "Bob")

childStore.get(nameAtom) // "Bob" — shadowed in child
rootStore.get(nameAtom) // "Alice" — parent unchanged
```

### Parent updates don't overwrite shadows

Once a scope shadows an atom, parent updates to that atom no longer affect the
scope:

```ts
rootStore.set(nameAtom, "Charlie")

rootStore.get(nameAtom) // "Charlie"
childStore.get(nameAtom) // "Bob" — still the scoped value
```

But atoms that the scope _hasn't_ shadowed continue to flow through:

```ts
const ageAtom = atom(30)
rootStore.set(ageAtom, 31)
childStore.get(ageAtom) // 31 — still reading from parent
```

### Reverting one value

`reset` removes the scope's own value, so the atom reads and tracks its parent's
value again:

```ts
childStore.reset(nameAtom)
childStore.get(nameAtom) // "Charlie" — the parent's value again
```

`reset` works on one atom or [collection](/valdres/collection) row at a time.
To discard all of a scope's edits, dispose it and start a new scope; see
[Lifetime](#lifetime).

## Selectors in scopes

Selectors automatically evaluate against the scope's view of state:

```ts
import { atom, selector, store } from "valdres"

const priceAtom = atom(100)
const taxAtom = atom(0.2)
const totalSelector = selector(get => get(priceAtom) * (1 + get(taxAtom)))

const root = store()
const child = root.scope("preview")

root.get(totalSelector) // 120

child.set(taxAtom, 0.25)
child.get(totalSelector) // 125 — uses child's tax, parent's price
root.get(totalSelector) // 120 — unchanged
```

## Collections in scopes

[Collection](/valdres/collection) rows follow the same rules. A child scope
inherits the parent's rows, its own inserts stay local, and `delete(row)` in a
scope hides an inherited row without touching the parent:

```ts
import { collection, store } from "valdres"

type Todo = { title: string; done: boolean }

const todos = collection<string, Todo>()
const root = store()
const child = root.scope("draft")

root.set(todos("a"), { title: "Buy milk", done: false })
child.get(todos("a")) // { title: "Buy milk", done: false } — inherited

child.set(todos("b"), { title: "Draft todo", done: false })
root.get(todos) // [todos("a")]
child.get(todos) // [todos("a"), todos("b")]

child.delete(todos("a"))
child.get(todos("a")) // undefined — hidden in the child
root.get(todos("a")) // { title: "Buy milk", done: false }

child.reset(todos("a")) // inherited again
```

## Subscriptions

Subscriptions within a scope react to changes in that scope's view of state:

```ts
const root = store()
const child = root.scope("child")
const countAtom = atom(0)

child.sub(countAtom, () => {
    console.log("child sees:", child.get(countAtom))
})

root.set(countAtom, 1)
// logs: "child sees: 1" — parent update flows through

child.set(countAtom, 99)
// logs: "child sees: 99" — scoped update

root.set(countAtom, 2)
// nothing logged — child has shadowed this atom
```

## Transactions in scopes

Transactions work the same way inside scopes:

```ts
child.txn(tx => {
    tx.set(nameAtom, "New name")
    tx.set(ageAtom, 25)
    // Both updates are atomic within the scope
})
```

A transaction on the parent can read and write its scopes through `tx.scope`,
so publishing a draft and reverting it land in one commit:

```ts
const root = store()
const draft = root.scope("draft")
draft.set(nameAtom, "Bob")

root.txn(tx => {
    tx.set(nameAtom, tx.scope("draft", scoped => scoped.get(nameAtom)))
    tx.scope("draft").reset(nameAtom)
})

root.get(nameAtom) // "Bob"
draft.get(nameAtom) // "Bob" — inherited from the parent now
```

Inside a transaction, use the cursor and `tx.scope`, not captured Store
handles: calling `draft.get(...)` there throws `TransactionPhaseError`.
`tx.scope(name)` throws `ScopeNotFoundError` if no live scope has that name.

## Lifetime

Scopes come in two kinds, and neither is reference-counted.

**Named scopes are shared.** While a scope named `"draft"` is alive, every
`root.scope("draft")` call returns the same handle. Names are per parent.

```ts
const first = root.scope("draft")
const second = root.scope("draft")
first === second // true
```

**`dispose()` ends a named scope for everyone.** Any holder can dispose it, and
every holder's handle is then terminal: later operations on it throw
`StoreDisposedError`. The next `scope("draft")` creates a new scope with no
local state:

```ts
first.set(nameAtom, "Bob")
first.dispose()

second.get(nameAtom) // throws StoreDisposedError
root.scope("draft").get(nameAtom) // the parent's value: a new scope
```

If several consumers share a named scope, decide which one owns its disposal.

**`scope()` without a name creates a new anonymous child on every call.** Use it
when one consumer needs its own isolated state and will dispose it:

```ts
const preview = root.scope()
preview.set(nameAtom, "Preview")
// ...
preview.dispose()
```

An anonymous child is not a lease on its parent. Its writes belong to the child
and disappear with it, and disposing the parent still disposes the child.

Disposing any Store disposes all of its descendant scopes. There is no
dispose hook; release anything you keep alongside a scope in the code that
calls `dispose()`.

## In React

`valdres-react` has no scope component. Create the scope outside render and
pass it to a nested [Provider](/react/Provider); hooks below it read and write
the scope. The code that creates the scope owns its disposal:

```tsx
import { store } from "valdres"
import { Provider } from "valdres-react"

const appStore = store()
const editorStore = appStore.scope("editor")

function App() {
    return (
        <Provider store={appStore}>
            <MainView />
            <Provider store={editorStore}>
                <Editor />
            </Provider>
        </Provider>
    )
}
```

Keep scope creation out of render: React can render more than once, so a scope
created there may be created twice, and an extra anonymous one stays alive
until its parent is disposed.

To publish a scope's edits to its parent in one commit, read the scope through
the parent transaction's cursor:

```ts
function saveEditor() {
    appStore.txn(tx => {
        tx.set(userAtom, tx.scope(editorStore, scoped => scoped.get(userAtom)))
        tx.scope(editorStore).reset(userAtom)
    })
}
```
