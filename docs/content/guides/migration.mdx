# Migration Guide

Valdres provides compatibility packages for both Recoil and Jotai. For the APIs a package supports, you migrate by changing an import — then gradually adopt the native Valdres API at your own pace.

## From Recoil

`@valdres-react/recoil` is a bounded migration adapter for the synchronous
part of Recoil's API. Replace your Recoil import:

```ts
// Before
import { atom, selector, useRecoilState } from "recoil"

// After
import { atom, selector, useRecoilState } from "@valdres-react/recoil"
```

  <div className="callout-title">Not yet released for Valdres 1.0</div>
  The Valdres 1.0 version of this package is not published yet. The published
  `@valdres-react/recoil@1.0.0-beta.3` targets the pre-1.0 core and does not
  load with current Valdres betas.
</div>

Its peers are `valdres`, `valdres-react` and React 18 or 19.

It is not complete Recoil compatibility. Atoms, selectors (including writable
ones), families, `RecoilRoot`, the state hooks and `useRecoilCallback` follow
Recoil 0.7.7, checked against Recoil itself, apart from documented differences. Async atoms and selectors, atom
effects, snapshots read after a callback's first `await` and some hooks are not
supported: using them throws `UnsupportedRecoilFeatureError` or fails to
import, rather than behaving differently. As Valdres extensions, the Recoil
hooks also accept native Valdres states and work under a `valdres-react`
`Provider`. Check the [support matrix](/guides/vs-recoil#the-migration-adapter)
before migrating.

<div className="callout callout-tip">
  <div className="callout-title">Why migrate from Recoil?</div>
  Recoil is no longer maintained and its last release does not run on React 19. Valdres is actively developed, has a zero-dependency core, and doesn't require string keys for atoms.
</div>

## From Jotai

`@valdres-react/jotai` is a partial implementation of Jotai 3's core API
(`atom`, `createStore`, `getDefaultStore`, `Provider`, `useAtom`,
`useAtomValue`, `useAtomValueRaw`, `useAtomValueRawSync`, `useSetAtom`,
`useStore`) on Valdres. Replace your Jotai import with it:

```ts
// Before
import { atom, createStore } from "jotai"

// After
import { atom, createStore } from "@valdres-react/jotai"
```

  <div className="callout-title">Not yet released for Valdres 1.0</div>
  The Valdres 1.0 version of this package is not published yet. The published
  `@valdres-react/jotai@1.0.0-beta.3` targets the pre-1.0 core and does not load
  with current Valdres betas.
</div>

It is not complete Jotai compatibility. It is checked against Jotai 3.0.1's own
test suite and side-by-side tests.

**Not supported:**

- **Dependencies read after `await`.** A read function's `get` must be called
  before its first `await`; a later `get` throws (`VALDRES_JOTAI_LATE_GET`).
  Promises as atom values, async read functions that read before their first
  `await`, and `await get(asyncAtom)` are supported.
- **Cancellation.** There is no `signal` in read options
  (`VALDRES_JOTAI_SIGNAL_UNSUPPORTED`); replaced promises are not aborted.
- **`unwrap`** from `jotai/utils`, `INTERNAL_onInit`, **store calls inside read
  functions**, and **`jotai/react/utils`** hooks.

**Different from Jotai:** derived atoms that were read once recompute when
their dependencies change even without subscribers, which also changes the
values of atoms that read their own previous value; a write that sets an atom
and restores it does not recompute or notify mounted derived atoms; and
`selectAtom` and `splitAtom` pass Jotai's tests but can return new, equal
objects where Jotai keeps the previous one. Most other `jotai/utils` helpers
and `jotai-family` work with this package's store.

The [compatibility notes](https://github.com/eigilsagafos/valdres/blob/main/packages/@valdres-react/jotai/COMPATIBILITY.md) list every difference and how each was tested.

## Gradual adoption

Once you've migrated, you can incrementally adopt the native Valdres API:

1. **Replace imports** — Switch from `@valdres-react/recoil` or `@valdres-react/jotai` to `valdres` and `valdres-react` (the Recoil hooks also read and write native Valdres atoms, and work under a `valdres-react` `Provider`; see [Valdres extensions](/guides/vs-recoil#valdres-extensions))
2. **Use native hooks** — Replace `useRecoilState` with `useAtom`, `useRecoilValue` with `useValue`
3. **Adopt new features** — Start using transactions, first-class families, and framework-agnostic state

```ts
// Compatibility layer
import { atom } from "@valdres-react/recoil"
import { useRecoilState } from "@valdres-react/recoil"

// Native Valdres
import { atom } from "valdres"
import { useAtom } from "valdres-react"
```

## Key differences from Recoil

| Feature | Recoil | Valdres |
|---------|--------|---------|
| Atom keys | Required string keys | No keys needed (identified by reference) |
| Dependencies | Several | Zero (core) |
| Maintenance | Abandoned | Actively developed |
| Families | Utility | First-class primitive |
| Framework support | React only | React, Vue, Svelte, Solid, Angular |

## Key differences from Jotai

| Feature | Jotai | Valdres |
|---------|-------|---------|
| React integration | useEffect + useReducer | useSyncExternalStore |
| Atom types | Unified atom concept | Separate atom + selector |
| Families | Community utility | First-class with subscription |
| Transactions | Not explicit | Built-in `store.txn()` |
| Framework support | React only | React, Vue, Svelte, Solid, Angular |
